# Kudio 1.6.2 更新报告与运行说明

日期：2026 年 10 月 4 日。本文说明 1.6.2 整理后的界面、数据保存方式、推理流程与 PCS 支持范围。行为以当前程序实现为准；PCS / KSON 的详细格式见 [PCS_KSON.md](PCS_KSON.md)。

本次发布把前端重建、多角色配音和三语界面整理为可维护的本地工作台，并补充运行说明与 PCS 编写技能交付。本报告同时随 Windows 发布包提供，PCS 技能目录可独立复制安装。精简明细、验证结果和发布位置见第 12 节。

## 1. 界面与工作区

界面采用蓝色主色，支持简体中文、English、日本語，语言选项保存在当前浏览器的 `localStorage` 中。切换界面语言会刷新文案和状态显示，保留当前作品、编辑草稿、选中的角色与正在播放的音频。用户正文、作品名、角色名、标签、文件路径、引擎日志和高级 JSON 不作为界面文案翻译。

界面语言与配音语言独立。例如，英文界面可以使用日语角色，也可以朗读中文正文。角色的正文语言支持 `zh / en / ja / auto`；参考音频语言支持 `zh / en / ja`。这些选项决定提交给 GPT-SoVITS 的语言参数，不随界面语言切换。

左侧分为三个主工作区：

| 工作区 | 用户操作 | 保存与运行责任 |
| --- | --- | --- |
| 配置 | 分为引擎设置、角色库；选择引擎与素材目录，保存可复用角色 | 配置机器路径与角色预设，不直接改写作品正文 |
| 文本 | 导入 TXT / PCS、编辑正文、预览分段、设置默认角色与声音标签映射 | 将明确应用的源稿、分段计划和配音安排保存到作品 |
| 推理 / Generate | 启动生成、查看进度、试听、单段重做、导出 | 按已保存的计划生成 WAV，完成实测时间轴与交付文件 |

左侧作品目录承担作品切换、检索和归档显示；右侧流程区补充当前进度。点击流程步骤可打开大弹窗，阅读简洁说明，再按需展开解析结构、推理计划和原始数据。日常操作不需要理解 AST 或编辑 JSON。

角色以卡片展示，支持名称、介绍、标签、颜色、头像和立绘。角色名称为 1–80 字；介绍最多 4000 字；标签最多 20 个、每个 1–40 字；颜色为六位十六进制值。图片支持本机 PNG、JPEG、WebP、GIF，最大 20,000,000 字节，后端核验文件签名。图片路径登记并保存角色后才用于预览，不提供任意路径的图片读取接口。

## 2. 从文本到作品的运行逻辑

程序的主要链路如下：

```text
TXT / PCS 原始文本
  → 明确选择文件格式
  → 后端解析与校验
  → 在控制边界内自然分段
  → 保存源稿、片段与有序计划
  → 默认角色 / 声音标签映射到作品角色快照
  → 逐段切换模型并调用本地 GPT-SoVITS
  → 保存片段 WAV 与真实时长
  → 统一音频时间轴
  → WAV / SRT / KSON 导出
```

前端负责编辑、显示和操作；后端负责正式解析、参数继承、任务锁、文件写入、音频校验与导出。预览解析和预览分段不会调用 TTS，也不会替换已有作品。

| 后端模块 | 作用 |
| --- | --- |
| `server.py` | 本地 HTTP、接口、目录选择、作品存储、引擎与队列生命周期 |
| `pcs.py` | PCS 词法、语法、有效值校验和源码定位诊断 |
| `compiler.py` | 控制状态、分段计划、片段指纹与成功音频复用 |
| `projects.py` | 项目 schema 迁移、原子应用源稿、检查计划是否过期 |
| `roles.py` | 默认角色、PCS 标签映射、作品角色快照与显式同步 |
| `tts.py` | 有效声音参数、TTS 请求与返回 WAV 校验 |
| `timeline.py` | 用同一 PCM 帧时钟计算语音、停顿和控制事件 |
| `exporters.py` | 按该时间轴写出 WAV、SRT 和 KSON |

后端仅使用 Python 标准库，前端使用原生 HTML / CSS / JavaScript，不需要 npm 安装。推理运行环境来自用户所选 GPT-SoVITS 整合包；Kudio 发布包不附带 Python、引擎、模型和个人素材。

## 3. 角色库、作品快照与配音安排

角色库是跨作品复用的素材；作品拥有自己的配音配置。首次为作品选择角色时，程序复制该角色的 `voice` 和 `profile`，保存为作品快照：

```text
default_role_id                 默认角色 ID
voice_bindings                  声音标签 → 角色 ID
role_snapshots                  角色 ID → 已保存角色配置
voice                           当前作品的默认声音配置
```

TXT 始终使用一个默认声音。没有 `voice` 标签的 PCS，以及第一个 `voice` 标签之前的正文，使用默认角色；旧作品也可沿用原有 `voice` 配置。全新的作品需要先选择有效的默认角色，或为实际使用到的声音标签完成绑定。

`#[voice:male_elder]#` 中的 `male_elder` 是声音特征标签，不是角色库名称、模型路径或文件名。在文本页，可以把它分配给任意已保存角色；`female_child` 等其他标签可以分别分配不同角色。标签只影响其后的正文；正文中实际使用到的标签未绑定时，作品可以保存和预览，但不能启动正式推理。末尾没有正文的孤立 `voice` 标签不产生额外绑定需求。

修改或删除角色库预设不会立即改变已有作品的声音。普通保存配音安排保留已存在的角色快照；“同步角色库配置”才明确采纳所选角色的新库配置。角色页“保存并设为默认角色”会同步此次保存的角色。已从库中删除的角色仍可沿用作品内的声音快照，主动同步则需要改选仍存在的库角色。模型、参考音频等外部文件若被移动或删除，快照本身不能恢复这些文件。

有效参数按以下顺序确定：

```text
PCS 显式 rate
  > 单段参数覆盖
  > 当前绑定角色的作品快照
  > 作品默认 voice / 内置默认值
```

每段可以覆盖 `speed、seed、text_lang、reference、prompt、prompt_lang`；当前片段接口不接受 GPT / SoVITS 模型的单段覆盖，模型随角色安排选择。角色的语速为 0.5–2.0，作品默认片段间隔 `gap` 为 0–3 秒。PCS 没有 gap 或 seed 指令。

修改绑定只将合成参数实际变化的相关片段置为待生成，其他音频保留。角色 ID 或显示名变化但合成参数相同时，WAV 保留，旧导出列表失效，以便下一次 KSON 导出反映新的角色身份。角色介绍、图片、标签和颜色不参与 TTS 音频指纹。

## 4. 当前支持的 PCS 语法

PCS 使用 UTF-8 纯文本 `.pcs` 文件，正文与内联控制共同编写。Kudio 导入时先尝试严格 UTF-8，失败后尝试 GB18030；发布技能生成的文件统一使用 UTF-8 和小写 `.pcs` 扩展名。

基本形式为：

```text
#[command:value]#
```

指令名去除两侧空白并转为小写，值去除两侧空白。只按第一个 `:` 分隔，因此 `#[section:part:one]#` 的章节名为 `part:one`。声音标签、章节名本身保留大小写。

| 指令 | 合法值与示例 | 运行含义 |
| --- | --- | --- |
| `p` | ASCII 十进制正整数，例如 `#[p:1]#`、`#[p:12]#` | 后续语音继承页码，直到下一个 p；重复或递减页码也可解析，当前后端不自动改写或生成递减警告 |
| `pause` | ASCII 十进制整数 0–30000，单位毫秒，例如 `#[pause:800]#` | 在该位置插入静音；显式 0 也替代该边界的默认段间停顿 |
| `rate` | 普通十进制数 0.5–2.0，例如 `#[rate:0.9]#`、`#[rate:.8]#` | 持续改变后续语速，映射为 `speed_factor`；不接受正负号、科学计数、NaN 或 Infinity |
| `section` | 去除两侧空白后 1–80 个 Unicode 字符，例如 `#[section:开场]#` | 后续语音继承语义章节名；名称可含冒号 |
| `voice` | 去除两侧空白后 1–80 个 Unicode 字符，不含码位小于 32 的控制字符，例如 `#[voice:male_elder]#` | 后续正文继承该声音标签，在文本页绑定实际角色；标签内部不得包含换行或 Tab |

五种控制都形成分段硬边界。程序先沿控制拆开正文，再在每个正文区间内按段落、标点与字数自然分段；不会把标签两侧的正文合并成一次推理。Page、Rate、Section、Voice 持续生效；Pause 是一次性事件。初始 Page、Section、Voice 为未指定，Rate 未指定时继承有效角色语速。

连续控制支持共用一个 `#` 和完整相接两种写法，语义一致：

```text
#[p:1]#[rate:0.9]#正文
#[p:1]##[rate:0.9]#正文
```

在 PCS 中，紧邻 `#[` 前的一个反斜杠把该标签转成朗读文字，仅移除这一条反斜杠：

```text
显示 \#[p:1]# 字样。
```

以上正文实际朗读为“显示 #[p:1]# 字样。”，不产生换页事件。转义延伸到第一个 `]#`；没有闭合时延伸到文本结尾。PCS 不提供额外通用转义、变量、表达式、循环或宏。

文件格式必须明确指定。导入 `.txt` 使用 TXT 模式，导入 `.pcs` 使用 PCS 模式；直接粘贴默认 TXT。TXT 不检测或执行标签，即使出现 `#[voice:...]#`、未知标签、未闭合标签和反斜杠，也作为普通朗读文字。只有 PCS 支持标签控制多角色。

以下情况在 PCS 中产生带行列和源码范围的错误：未知指令、缺少冒号、非法值、未闭合标签、嵌套标签、无对应起始标记的 `]#`。含错误的编译结果没有片段与执行计划，不能推理或正式导出；修正失败也不会覆盖原来已成功保存的计划。合法控制不会进入朗读请求，显式转义的字面标签除外。

### 多角色示例

```text
#[p:1]#[section:开场]#这里是旁白，由作品默认角色朗读。
#[voice:male_elder]#孩子，今天我们去看海。
#[pause:800]#[voice:female_child]#[rate:1.1]#好呀！我已经准备好了。
#[p:2]#[section:海边]#他们来到岸边。
```

最后一句仍由 `female_child` 朗读，并继承 1.1 倍语速，因为 Voice 和 Rate 持续生效。需要换回旁白时，应明确加入另一个标签，例如 `#[voice:narrator]#`，并在文本页把 `narrator` 绑定到旁白角色；当前没有“清空 voice 回到默认值”的特殊标签。

PCS 的 Page 只是时间轴中的语义页码。程序不打开 PPT、不操作鼠标，也不执行 `focus、cursor、highlight、zoom、click、transition` 等未来或外部指令；这些在当前解析器中属于未知指令。

## 5. 编辑、应用编译与音频复用

源稿项目以 `source_text` 为唯一正文来源。文本页修改正文、格式或分段字数时，只更新当前浏览器会话中的草稿，旧音频与已保存计划暂时保留；刷新浏览器前应应用需要保留的修改。

“预览分段”请求后端解析和编译，展示问题、正文片段与控制信息；“应用文本修改”才将源稿、哈希、AST、诊断、片段和计划一起写入 `project.json`。作品创建与源稿应用的分段字数范围为 40–500，默认 160。解析/编译是独立的无推理过程，不等于启动语音生成。

应用时按照正文与控制作用域匹配旧片段，再用指纹检查有效模型和完整 TTS 参数。完全一致的片段复用已生成音频及版本信息；新增或声音发生变化的片段等待生成。重复正文按原顺序匹配，每个旧 ID 最多复用一次。只改变显式停顿时，未改变的语音可以复用，时间轴和导出会重新计算。

源码未应用、解析有错误、配音安排未保存或使用到的声音标签未绑定时，界面阻止生成与导出。后端另行检查源稿哈希、诊断和语音计划是否一致，避免使用过期计划。单段窗口只修改声音参数和发起重做；源稿项目的正文仍在文本页修改。

片段重做前可保留上一版 WAV 和参数。恢复上一版时必须同时满足当前声音指纹和源稿语义一致，不能把不同文字、不同语速或不同声音的旧音频直接标成当前版本。

## 6. 推理队列、暂停与失败恢复

Kudio 工作台监听 `127.0.0.1:8765`，GPT-SoVITS API 使用 `127.0.0.1:9880`。启动引擎后先加载依赖与模型，界面显示运行状态和日志；正式生成前确认引擎已在线。整合包初始化速度与所需显存由所选模型和硬件决定。

同一时刻只运行一个作品的推理队列。队列按片段顺序处理 `pending`；已有 `done` 音频跳过，`failed` 不会自动伪装成待生成。每段先解析对应角色快照，模型组合变化时载入该角色的 GPT 和 SoVITS；参考音频、参考台词和语种随该段请求提交。

当前 TTS 请求固定使用 `cut5`、`batch_size: 1`、`parallel_infer: false`、`streaming_mode: false` 与 WAV 返回。模型切换若只成功一部分，会清空本地已加载组合记录，下次尝试或换回其他角色重新加载两套模型，防止误用混合组合。

每段最多尝试三次。返回结果必须为非空、完整、未压缩 PCM WAV，真实时长从帧数与采样率计算；写入临时文件后替换正式 WAV。完成、失败、错误与版本信息随后保存。连续三个片段最终失败时，队列暂停并显示错误。

“暂停”停止后续片段，已开始的当前推理尽量完成并保存。若当次调用已经失败，停止信号可以终止后续重试。队列真正结束后才能修改当前作品或导出。“重试失败”将失败片段恢复为待生成；“单段重做”只处理目标片段。下次启动会将中断留下的 `running` 恢复为 `pending`，已标完成但 WAV 缺失的片段也回到待生成。

## 7. 试听与统一时间轴

试听先把选中 WAV 读取成浏览器 Blob，再创建临时对象 URL 播放。播放器独立于刷新的片段列表，队列进度刷新不会重建正在播放的音频；磁盘同名 WAV 被重做替换时，已载入的 Blob 仍是当前试听版本。切换或停止播放时释放旧对象 URL。可以连续试听、前后切换片段，选择跳过未生成片段，或等待对应片段生成后继续。

连续试听以片段为单位推进；完整作品的最终停顿与精确时序以正式导出的 WAV 和统一时间轴为准。

尚未完成时，时间轴为 `estimated`。未知语音依据正文长度和有效语速估算；未知片段之后的累计位置也标记为估算。所有选中音频完成且 WAV 校验通过后，时间轴为 `exact`，使用实际 WAV 帧数，忽略缓存的时长值。

时间轴统一处理语音、控制与静音：

- 相邻语音之间没有显式 Pause 时，使用作品 `gap`。
- 显式 Pause 包括 0ms，替代该边界的默认间隔；连续 Pause 累加。
- 整本导出保留开头和结尾 Pause；控制事件按原文顺序落在当前时刻。
- 同一时刻的控制不按类型重新排序；页码、章节、声音和语速保留其相对顺序。
- 分组范围从 0 重新计时，并恢复范围之前最后的 Page、Rate、Section、Voice 状态，不带入范围外的停顿。
- 混合采样率、位深或声道的 WAV 使用引擎自带 ffmpeg 在临时文件中统一格式，原片段不改写。

内部累计整数 PCM 帧，出口统一四舍五入成毫秒。小到无法表示正整数毫秒区间的音频会报错，不凭空补造准确时间。

## 8. WAV、SRT 与 KSON 交付

整本和已确认分组可以导出 WAV；WAV 导出同时生成同名 SRT / KSON，也可单独导出 SRT 或 KSON。所选范围必须全部完成并可建立实测时间轴；分组导出不要求范围之外的片段已完成。章节与“智能分段”建议仍需用户采纳或手动确认，目前没有运行 AI 分段代理。

三个格式消费同一时间轴，而不是各自重新估算：

| 格式 | 内容与边界 |
| --- | --- |
| WAV | 语音和已计划静音的合并 PCM；流式写入，检查标准 RIFF 约 4 GB 上限 |
| SRT | 每个朗读片段一个字幕区间；含片段之间的静音间距，不是逐字强制对齐 |
| KSON | 标准 JSON，`format: kson`、`version: 0.1`、`timebase: ms`；记录正文区间、控制事件、源码信息与角色元数据 |

KSON 的 `segments` 记录正文、起止毫秒、页码、章节、实际语速，并可附带 `voice_label / role_id / role_name`。`events` 单独保留 Page、Pause、Rate、Section、Voice 的事件顺序；当前实际字段分别使用 `page`、`label`、`name`、`value` 等，不应把技能参考里的概念示例直接当作正式导出结构。Pause 还包含起止时刻、实际毫秒长度和请求毫秒数。

预览 KSON 允许 `estimated`；正式文件只输出准确的选中范围。导出文件采用临时文件写完后替换，避免失败时留下半份正式输出。

## 9. 配置、数据落地与进程退出

程序按自身目录定位文件，目录名不需要固定为 `Kudio_Local`。下表中的 `<Kudio目录>` 指实际启动程序所在目录。

| 路径 | 用途 |
| --- | --- |
| `<Kudio目录>/settings.json` | `engine_root`、可选 `model_root`、`reference_root` |
| `<Kudio目录>/data/projects/作品名--32位ID/project.json` | 已保存源稿、格式、schema、片段状态、计划、角色快照、分组与导出记录 |
| 同一作品目录中的 `<segment_id>.wav` | 当前片段音频；可能另有 `-previous.wav` 上一版 |
| 同一作品目录中的 `exports/` | WAV / SRT / KSON 交付文件 |
| `<Kudio目录>/data/voice_presets.json` | 跨作品角色库 |
| `<Kudio目录>/data/path_history.json` | 不同选择用途的最近目录 |
| `<Kudio目录>/data/trash/` | 可恢复的作品回收站，仍占磁盘空间 |
| `<Kudio目录>/data/engine.log`、`training.log` | 推理引擎、官方训练面板日志 |
| `<Kudio目录>/data/tts_infer.yaml` | 首次启动从引擎配置复制的推理设置 |
| `<Kudio目录>/data/cache/` | 引擎 / 训练运行所需的临时与缓存目录 |

模型、参考音频和角色图片通常保存在用户外部素材目录，作品与角色库保存其路径，不把这些文件复制进发布包。浏览器另记忆界面语言、当前作品及导航页面；未应用的编辑草稿只在当前页面会话中保留。

引擎目录需要包含 `api_v2.py` 与 `runtime/python.exe`。启动脚本优先读取 `settings.json`，未配置时尝试识别相邻目录唯一的一套整合包；否则要求用户选择。启动配置可读取相对引擎路径，应用内目录保存接口要求存在的本机绝对目录。改变已运行程序的引擎目录后，需要退出并重新启动 Kudio 才更换实际运行引擎。

应用内目录选择使用 Windows IFileDialog 的现代文件夹模式，文件选择启用系统现代文件框；各用途分别记住最近目录，取消选择不更新记忆。当前启动脚本 `launch.ps1` 的初次配置窗口仍使用其原有文件夹浏览器，现代化改造不应被理解为已替换所有启动入口。

官方训练面板入口运行所选整合包的上游 `webui.py`，通常访问 `127.0.0.1:9874`。打开面板不自动开始训练；数据准备、特征提取和 GPT / SoVITS 训练由用户在上游面板配置。Kudio 的三语切换不改写上游训练界面。训练有独立缓存目录，当前独立训练任务在退出 Kudio 后继续运行。

“停止引擎”先通知队列结束，等待当前片段保存，再停止 Kudio 启动的 TTS 子进程；若引擎已独立启动，则先核对 9880 服务接口，再请求其退出。“退出 Kudio”在上述流程后关闭工作台 HTTP 服务，浏览器页面可关闭；仅关闭浏览器标签页并不等于退出后端。此流程不批量终止所有 Python 进程，也不自动终止独立训练面板。模型启动日志与作品状态用于排查失败。

## 10. 建议用户操作流程

1. 将程序置于可写目录，双击 `启动Kudio.bat`；需要换整合包时用 `配置引擎.bat`。确认引擎目录有效。
2. 在配置工作区选择模型、参考音频目录并扫描。角色页填写 GPT、SoVITS、参考音频、参考音频实际说出的文字及语种，保存角色；图片与介绍可一并填写。
3. 在文本页创建作品，导入 `.txt` 或 `.pcs`，确认格式与每段字数，预览片段；有错误时从提示定位到源稿修正。
4. 保存或应用正文。普通文本选择默认角色；PCS 为所有实际使用到的声音标签选择角色，然后保存配音安排。
5. 启动引擎并等待在线，进入推理工作区开始生成。可以暂停、重试失败、单段试听和重做；声音修改前先让当前队列结束。
6. 修改源稿后重新应用；修改角色库后，如希望已有作品采纳变动，明确点击同步。观察受影响片段回到待生成，而其他音频保持完成。
7. 全部完成后导出整本，或确认分组并导出完成的范围。核对 SRT / KSON 与 WAV；需要精确事件时序时使用正式实测导出。
8. 结束时保存修改并使用“退出 Kudio”。归档用于整理列表；删除作品先移入回收站，永久清理需输入完整作品名确认。

## 11. 升级保留数据与当前能力边界

升级前先应用需要保留的浏览器草稿，退出 Kudio，备份整个 `data/` 与 `settings.json`；外部模型、音频和图片仍由用户保管。更新程序文件时不要用发布包覆盖或删除本机数据。发布白名单不包含个人配置、作品、日志和缓存。

当前项目 `schema_version` 为 2。旧项目启动时补充元数据，迁移前保留 `project.schema-1.backup.json`，保留原片段 ID 和 WAV；没有原始源稿的作品标记为 `legacy`，以旧片段继续运行，直到用户明确应用重建源稿。高于当前支持 schema 的项目会拒绝打开，避免向下损坏。

需要理解的边界如下：

- 当前仅支持本地 Windows GPT-SoVITS 流程；其他引擎版本的兼容性、声音质量、显存要求与速度需实际验证。
- 当前不提供 PPT 操作、视频生成、自动镜头、变量脚本或 AI 智能分段；Page、Section 等主要是语义与时间轴控制。
- `.pcs` 是源稿，`.kson` 是导出时间轴；角色描述和声线标签不会自动转化成性别、年龄或情绪模型参数。
- 当前推理是单作品队列、片段顺序生成，不提供多队列并行或流式边生成边播放。
- SRT 是片段级字幕，未知时长为估算；未经生成不能称为准确时轴。
- 单个标准 WAV 有 RIFF 大小限制，较长作品应按范围导出。
- 未应用草稿刷新会丢失；切换语言不会因此改写草稿或配音语言。
- 模型路径不变但文件内容被替换时，指纹不能自动识别，需要主动重做。外部素材路径迁移后需要重新配置。
- 编译删除或改动片段后，旧 WAV 可能暂留作品目录；它们不会进入当前计划或正式导出。本次目录精简不等于自动清除所有用户音频历史。
- 删除库角色后作品音频配置仍保留，但库中已删除的头像入口不会再显示该角色图片；独立训练任务需要单独管理。
- 本地服务不是公网部署方案，不包含云上传或遥测。

本报告不宣称已完成真实 GPU 推理验证或测得性能提升。代码回归可使用注入的合法 WAV 验证状态、模型切换和导出逻辑；可选真实引擎测试只有在配置可用模型与参考素材后运行，其结果需单独记录。
